# Clean Windows 11 installation test

On 12 November 2026, the published Streamsthetic 0.2.5 offline installer completed successfully in a fresh Hyper-V Windows 11 x64 VM. The installed app rendered and all four locally installed virtual cameras delivered changing video frames.

## Environment and installer

- Windows 11 Enterprise Evaluation, x64, build `26300.9457`.
- Guest networking disconnected during installation and capture.
- No .NET SDK, .NET Core or Windows Desktop runtime in the standard x64 installation directories. `dotnet.exe` was absent from PATH.
- Published `Streamsthetic-Setup-offline.exe`, SHA-256 `B615266AFBFD451F21B63EF27CF3B83A27428BAC3C2A1238B5D1CAD48A9965EF`. Setup exited with code 0. The installed executable matched the expected package hash.
- Camera setup logged successful permissions, COM and virtual camera registration steps. The installed receiver and camera source matched the package hashes. The app's rendered interface was inspected.

## Camera results

Four installed receiver processes replayed a synthetic source. Four Media Foundation readers captured NV12 at 1280 × 720, 30 fps. The readers required a local source with the expected camera name and rejected redirected sources. Each reported strictly increasing timestamps.

| Camera slot | Frames read | Distinct sampled frame hashes | Reader exit | Receiver exit |
| --- | ---: | ---: | ---: | ---: |
| 1 | 90 | 86 | 0 | 0 |
| 2 | 90 | 86 | 0 | 0 |
| 3 | 90 | 86 | 0 | 0 |
| 4 | 90 | 86 | 0 | 0 |

This covers fresh installation with the bundled runtime, application rendering and frame delivery for one synthetic workload. Physical phone streaming, USB compatibility, GPU decoding, upgrade and complete camera removal remain outside this run.

The earlier [Windows Sandbox report](2026-11-12-windows-sandbox.md) records access denied during camera startup. The failure did not reproduce in this full VM.
